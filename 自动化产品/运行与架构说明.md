- `9e8aeb5` 之后的修复仍属本地候选，不能描述为已上线；部署前必须重新核对 `docs/version.md`、Git 提交和服务器实况。
- v140 保留 8787 主服务 + 8765 回环 sidecar + 无限画布静态闭包的拓扑，在 v137/v139 基础上新增 deny-by-default resource scope、私有媒体 owner/team registry、fresh v2 备份事务绑定、完整 runtime snapshot/restore、精确离线依赖和启动前 write gate。RO release 可用于迁移验收；RW 必须在全部生产证据通过后明确 `writeReady=true`。
- v140 锁定主服务基线为 FastAPI 0.68.1 / Starlette 0.14.2 / Pydantic 1.10.26；生产 18 项运行锁与 20 项一次性测试锁严格隔离，测试锁只新增 requests/urllib3。视频 sidecar 为 37 项运行锁，显式包含 ctranslate2 所需的 `setuptools==83.0.0`。正式 wheelhouse 除哈希/ABI 验签外，必须从一次性 venv 以 `--no-index --no-deps` 安装并通过 exact-installed 与 `pip check`；setuptools 不再属于可忽略额外包。无 `.env*`、`env -i`、CPython 3.12.13 的干净主服务全量收集 `702` 项，`701` 项通过，唯一允许跳过项是 Git 提交不携带的旧 v120 只读快照；当前候选的视频 sidecar `139/139`、Node `117/117`，其他 skip 会失败。release verifier 当前为 60 个 ESM 模块/342 条边、63 个画布文件和 55 个 backend/video runtime 文件。较早 v120 副本只证明 7,044 条文档的 ACG/resource 迁移、100% scope 和第二轮零写幂等；因不含完整媒体，它不能替代当前生产的冻结 snapshot/media 演练。
- complete snapshot 的恢复语义包含普通文件精确 `mtimeNs`：安全解包后逐文件无链接跟随地恢复 manifest 纳秒值，并以 `lstat` 严格复核；文件系统若舍入即 fail closed。原因是生产媒体 inventory digest 同时绑定 path、size、mtimeNs 和内容 SHA-256，不能把“内容一致”误报为“同一恢复点”。`927bd29` 的生产形状副本已暴露最多 120ns 的 tar 恢复漂移，必须从修复后的唯一提交重做完整快照、恢复和第七步 media-preflight。
- v139 本地已将主服务、无限画布和视频工坊已识别模型入口统一为逐次 upstream attempt 的 durable receipt，并以 completion spool、projection outbox、后台重放和 readiness 指标处理 SQLite 完成写失败；v140 对同进程并发写增加 receipt 专用微批协调，每项保留独立 savepoint，整批提交成功后才授权上游，不使用全局 `store._lock`，跨进程仍由 SQLite 唯一约束裁决。它仍是应用侧事实账本而非供应商账单，生产 v120 尚未获得这些能力；历史缺口只能从只读证据形成下限 observation，不能猜补 token、调用次数或日期。
- 批量真人/数字人、图文和静态任务统一使用失败终态：上游/准备阶段失败写 `failed` 和可读原因，只有用户明确重试才重新派发；`evaluate`、JobRunner 和刷新恢复都不把 failed 当 pending。旧等待上传状态只在水合兼容层被幂等降为 failed，运行 UI 不再存在等待补图卡或跨任务自动补洞；主动上传仍由任务行、详情、计划参考图和资产入口明确触发。
- 远端水合后会对当前 owner 的视频 running 状态做幂等终态收敛：成片已在则 review，完整 succeeded 分段只执行 compose，失败/缺段/缺输出则 failed。`140005` 的服务端持久账本以 owner + production/timeline 指纹原子裁决 compose；跨标签页只生成一份成片，成功与媒体归属同事务提交，失败可重试。前端 `composing` 仅为展示态，pending 或浏览器停止等待不会误写 failed，下一次水合会查询同一账本。该恢复器不调用 provider、不创建 job、不扣费，并可收敛无 batch、done batch 残留状态和空转 generating batch。
- 供应商下载交付 ZIP 时，私有媒体是“交付关联读”而非团队成员读：必须同时命中当前 supplier parent/child 可见的持久交付和该交付精确引用的 cover/pack/source/final media。该例外仅作 GET/Range，不授予其他私有 URL、删除或覆盖；任一必备媒体失败都中止 ZIP 并显示原因。
- 视频工坊对话自动跟随只允许写 `.conversation-column` 的内部滚动状态。显式发送跟随底部；轮询重绘仅在用户原本接近底部时继续跟随，阅读历史时恢复原 `scrollTop`。禁止对消息节点调用会滚动 iframe 外层祖先的元素定位 API。
- 供应商交付的播放/曝光 triplet 由专用服务端端点维护；泛用资产快照即使携带更新的 `updatedAt` 也不得覆盖计数、时间和操作人。供应商页仅在进入和窗口重新聚焦时轻量拉取权威 `accounts/assets`，更新失败必须显示错误。
- Free 用户的图片、视频和语言对话在调用上游前预占真实积分，成功结算、失败释放，幂等重放不再扣费。“踢出团队”只移除席位，账号和资料保留并回到 Free；ACG 市场部 owner/admin 可停用或恢复创作端账号，停用后 Bearer、私有媒体 cookie 和视频工坊 cookie 均 fail closed。

## 默认任务执行与检查规范

除非用户明确缩小或扩大范围，按下面的分级执行。所有检查都以不覆盖用户修改、不写生产数据、不触发真实付费链路为前提。

### 0. 只读、问答与文档评估

- 用户明确要求“只读”“不要改代码”或只是询问架构时，只调查和报告，不修改项目。
- 可以读取相关文件、Git 状态和已有测试结果；不启动真实生成、发布、部署或外部写入。
- 纯文档修改只需要检查 Markdown 内容、链接、Git diff 和敏感信息，不需要启动整套产品。

### 1. 本地快速烟测（代码改动的默认级别）

用户没有额外说明时，完成本地代码修改后默认执行与改动范围匹配的快速烟测：

1. 检查 `git status --short` 和 `git diff --check`，确认没有误碰无关文件。
2. 对改动的 JavaScript 运行 `node --check`；对改动的 Python 运行编译检查。
3. 运行最相关的定向测试，不默认跑与本次无关的全部测试矩阵。
4. 服务已启动时检查相关健康接口；未启动时，仅在启动不会安装未知依赖、覆盖状态或触发外部任务的情况下启动本地服务。
5. 涉及可见前端页面时默认只跑源码与自动布局烟测；只有用户明确要求浏览器检查、视觉回归或手动验收时，才打开浏览器并覆盖指定视口。
6. 明确区分“自动测试通过”“浏览器快速烟测通过”和“用户已手动验收”，不能把前两者写成用户验收完成。

本地快速烟测不包括：真实图片/视频/语音付费生成、真实发布、供应商回传、批量写业务数据、Git 推送、服务器部署或生产数据修改。

### 2. 自动扩大为针对性验证的情况

出现以下任一情况时，应在快速烟测基础上增加相应测试和读写闭环验证：

- 修改登录、游客、成员、团队、供应商或角色权限。
- 修改积分预占/结算、订阅权益、支付展示或模型调用计量。
- 修改 SQLite schema、数据迁移、草稿同步、Blob、上传、删除、发布、回撤或幂等逻辑。
- 修改视频长任务、取消、恢复、重试、媒体合成、字幕或缓存标识。
- 修改无限画布源码、托管 vendor、父子应用消息协议或 iframe 鉴权。
- 修改批量生产与单号生产之间的项目映射、资产归属或交付状态。
- 修复曾经发生过的数据覆盖、权限串数据、白屏、缓存混版或部署差异。

针对性验证应覆盖涉及的单元测试/API、必要的浏览器流程、失败分支和数据非回退检查。涉及真实付费调用或生产写入时仍需用户明确授权，不能因为风险高就自行执行。

### 3. 完整验收与生产操作

- 只有用户明确要求“仔细验收”“完整视觉回归”“真实生成”“发布”“提交/推送”或“部署”时，才进入对应完整流程。

## 主业务模型

核心生产对象为 `production`：

- 图文：图文创作台 -> 审核 -> 交付。
- 数字人：数字人制作 -> 智能混剪 -> 审核 -> 交付。
- 信息流/素材视频：视频生成与素材编排 -> 智能混剪 -> 审核 -> 交付。
- 批量生产负责账号选择、账号级文案、参考图和批次启动；单号工作台负责具体生产、修正与交付。

账号、成员、团队、供应商、资产、发布和分析等权威业务数据由主服务控制。前端隐藏按钮不能替代服务端权限校验。

## 定制创作边界

### 视频工坊

- 独立 FastAPI sidecar 监听 `127.0.0.1:8765`，隔离新版 FastAPI/Pydantic、`faster-whisper`、FFmpeg 和长时媒体任务。
- 主平台通过 `/custom-video/` 签发当前成员会话、限制 owner 范围并代理 API、附件和成片。
- 项目、上传和输出保存在 `runtime/video-workshop/`；成功镜头、口播和成片支持保留与恢复，不得被代码部署覆盖。
- 动态任务与静态任务使用独立执行链：动态进入 Seedance；静态使用图片分镜、TTS、字幕、BGM 和 FFmpeg 渲染，图片生成最多三路并发，不得把静态任务误送 Seedance。
- 静态分镜按口播语义、导演节拍、附件归属、全片统一风格和负约束规划；约一分钟且语义充足时通常可达 12 张以上，短口播允许更少，3–5 秒仅为软节奏。画面使用固定中心的连续单调慢速放大，不建立精确时长或强制口播约束。
- 每次新的生产请求从最近一次交付边界后重建导演上下文，并使用生产级 `reference_scope_id` 命名连续性参考图；无新附件的下一任务不得读取上一任务的附件或固定文件名 anchor。同一任务的恢复/重试则继续使用自己的 scope。
- 项目顶层 status 只表示当前对话/制作阶段，不覆盖已持久化 delivery/output 的完成状态。用户点击当前或历史成片发布时，必须从该项目的 canonical output ID 解析同项目站内媒体路径；空/失败/未完成 output、外链、穿越和跨项目伪造必须拒绝。
- iframe 与 `postMessage` 是账号、样式、事件和长任务隔离边界；没有真实性能证据和灰度回退方案前不取消。

### 无限画布

- 源码位于 `apps/infinite-canvas-source/`，生产托管产物位于 `vendor/infinite-canvas/`，由主服务在 `/XZ-Design/` 提供。
- React/Zustand 子应用负责画布交互、节点、视口、参考图和浏览器导出；模型密钥、权限、生成、编辑和服务端草稿由主服务负责。
- 项目摘要与本地 checkpoint 按成员分仓；完整草稿同步到服务端，使用 revision、冲突保护和删除 tombstone。
- 新生成图片先固化为 owner-scoped Blob URL，再写入画布 checkpoint；旧内联 Base64 草稿在正常读写时惰性迁移。
- 批量生成最多三路并发，并已有取消、超时、Blob 持久化和旧执行态中断恢复；最终单张失败的 partial 收尾与 expanded part 精确重试仍待完成，不能宣称其余兄弟任务必然保留。
- 当前静态产物由 `apps/infinite-canvas-source/` 源码构建，共 63 个文件、`1759226` bytes；相对路径、大小和 SHA-256 manifest 已校验，`vendor/infinite-canvas/` 已按该审计闭包精确同步，不再保留历史多余哈希文件。浏览器端供应商 Key 与直连 API 构建路径已禁用，Agent、生成、高清、变换和局部编辑统一经主服务鉴权、配额和 receipt。

## 身份、团队与积分边界

- 游客状态不是服务器成员身份，不得访问团队业务和受保护生成接口。
- 公共注册先建立个人账号；加入团队和团队角色通过后续申请、审批和成员关系决定。
- 团队所有者、管理员、编辑、普通成员和供应商角色的能力由服务端接口逐项校验。
- v140 严格资源模式要求受保护业务记录拥有唯一 personal/team scope；查询、写入和删除按服务端行为人及已持久化 owner/account/upstream scope 判定，`role=admin` 不能作为跨租户旁路。历史歧义在 `140002` 迁移前保持生产只读，不能由前端筛选或默认团队掩盖。
- v140 私有媒体模式要求 uploads、composed、画布 Blob 和视频工坊持久媒体具有唯一 owner/team registry；本人及同团队按归属访问，外部团队管理员拒绝。供应商不是 team member，只能通过其确实可见的交付 ID 精确读取该交付引用的媒体，不获得任意媒体或写/删权限。社区已发布媒体通过独立公共边界读取，不能把公共帖子的例外扩大为任意直接 URL 权限。
- 个人每日积分和外部有限套餐在模型调用前原子预占，成功后按实际用量结算，失败、取消或中断后释放；幂等键必须绑定请求摘要和任务终态。
- 动态视频在成功终态按提交模型与归一化请求时长对应费率结算；静态视频按本轮新生成图片及存在且本轮新生成的 TTS 实际用量结算，历史复用媒体不重复收费。ACG 市场部精确走无限积分旁路。
- 供应商初始凭据只允许在首次受控响应中出现，响应必须禁止缓存；不得写入日志、文档或聊天。

## 字幕与语音边界

- 数字人自动字幕以分段口播原文为内容真源，以每段实测音频或视频时长为时间边界。
- 信息流字幕只读取最终视频提示词中的时间段和可验证说话上下文，排除 UI、道具文字、元数据和导演说明。
- 视频工坊对用户主动上传的外部音频可在 sidecar 内使用 `faster-whisper`；该依赖和模型缓存与主平台字幕链隔离。

## 数据与部署边界

- 主业务数据位于服务端 SQLite、上传目录、合成目录和受控 Blob/runtime 路径；生产必须使用 release 目录外的固定绝对路径，不得随版本切换。
- `.env.local`、服务器环境变量、API Key、认证缓存、数据库、上传、成片、日志、浏览器状态和模型缓存不得提交 Git。
- `runtime/`、`server/canvas_blobs/`、`apps/video-workshop/.venv/` 和生产持久卷不得被静态同步覆盖。
- 当前前向迁移顺序固定为 `137003` schema、`137004` ACG 团队数据、`139001` usage receipt/outbox、`140001` resource scope schema、`140002` 历史资源归属、`140003` private media schema、`140004` 历史媒体归属、`140005` owner-scoped compose claim、`140006` 成员状态/媒体 settlement 账本。生产已完成到 `140004`；当前候选必须对 `140005`、`140006` 分别生成 fresh v2 备份并双跑，随后使用 fresh complete snapshot/media digest/当前库 identity 单独执行幂等 `media-settle`，只登记 plan 明确且无冲突的 post-140004 pending，二次执行零写。不得重放 `140004`、裸 SQL 或忽略 pending。
- `140002` 与 `140004` 都先做只读 preflight；真正 unresolved、ambiguous、缺文件、缺 owner 或 registry conflict 为硬阻断。人工 override 只能精确覆盖 preflight 报告的可复核孤儿，并绑定冻结库 identity、路径/逻辑摘要、schema/user version 和当次 fresh 备份 manifest SHA，不能硬编码生产 ID 或默认收编到 ACG。
- 所有生产 apply 都必须绑定紧接其前生成的 `acg-sqlite-backup-v2`，并在同一 `BEGIN IMMEDIATE` 重新核对当前源库 identity 与逻辑摘要；上一步成功后必须重新备份。完整生产恢复使用 `acg-production-complete-v1` 将 SQLite、uploads、composed、canvas blobs、usage spool、视频 runtime、BGM、模型缓存、环境、systemd 和 Nginx 绑定到同一 snapshot ID，独立验签并恢复到空隔离目录。模型缓存内部文件 symlink 与 Nginx sites-enabled 入口只能按 production 精确组件策略解引用；真实字节纳入哈希，恢复为普通文件，越界、环、dangling 或特殊文件继续 fail closed。
- 主服务与 sidecar 分别以精确 requirements lock 建立目标 Python/ABI wheelhouse；manifest、目标运行时和每个 wheel SHA-256 必须离线验签，并通过一次性 `--no-deps` 安装、exact-installed 与 `pip check` 证明依赖闭包。生产启动的 `installed` 门禁也强制执行 `pip check`。监听 socket 前还要执行 write gate；`/api/ready` 的 RO 通过不等于可写，只有迁移、资源/媒体覆盖、用量、路径、sidecar、画布与 release 门禁全部通过时才可报告 `writeReady=true`。
- v139 的 `MODEL_USAGE_COMPLETION_SPOOL_DIR` 必须位于 release 外持久根并与 SQLite 属于同一 snapshot。readiness 的 unresolved/outbox/spool pending/corrupt/conflict 任一异常都不得切流；历史恢复只能按 `scan -> apply(copy) -> reconcile-copy` 操作隔离数据库副本，禁止指向活动库或生产持久根。
- 生产运行 release 必须以 systemd `ExecStart`/`WorkingDirectory` 和实际进程 cwd 为准；已发现 `/data/.../current` 可能是滞后普通目录，不得把它当作运行代码指针。持久路径仍必须来自经审计的绝对环境变量，运行 release 与批准 SHA 不一致即停止。
- 当前代码侧安全机制已形成，但生产 RW 仍被最新完整 snapshot/restore、`140005/140006/media-settle` 双跑与零 pending、正式 Linux wheelhouse、资源/媒体实数与正负权限矩阵、usage reconciliation/性能和兼容前向回滚 release 阻断。`9e8aeb5` 不理解 `140006` 的停用状态，只能用于未产生新状态写入时的 RO 验收；长期 RW 回滚必须使用理解 `140006` 的禁用恢复器或恢复到迁移前完整备份。
- v140 发布/迁移唯一权威方案是 `deploy/README.md`、`docs/本地代码架构优化与服务器迁移部署方案.md`、`docs/ACG市场部生产团队迁移计划.md` 与 `docs/服务器部署交接指南.md`；当前不构成部署授权。

### 什么时候读取历史文档

- 遇到报错、白屏、缓存异常、布局回退、权限问题、数据覆盖风险、任务恢复失败或本地/服务器不一致。
