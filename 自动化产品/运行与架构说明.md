## 默认任务执行与检查规范

除非用户明确缩小或扩大范围，按下面的分级执行。所有检查都以不覆盖用户修改、不写生产数据、不触发真实付费链路为前提。

### 0. 只读、问答与文档评估

- 用户明确要求“只读”“不要改代码”或只是询问架构时，只调查和报告，不修改项目。
- 可以读取相关文件、Git 状态和已有测试结果；不启动真实生成、发布、部署或外部写入。
- 纯文档修改只需要检查 Markdown 内容、链接、Git diff 和敏感信息，不需要启动整套产品。

### 1. 本地快速烟测（代码改动的默认级别）

用户没有额外说明时，完成本地代码修改后默认执行与改动范围匹配的快速烟测：

1. 检查 `git status --short` 和 `git diff --check`，确认没有误碰无关文件。
2. 对改动的 JavaScript 运行 `node --check`；对改动的 Python 运行编译检查。
3. 运行最相关的定向测试，不默认跑与本次无关的全部测试矩阵。
4. 服务已启动时检查相关健康接口；未启动时，仅在启动不会安装未知依赖、覆盖状态或触发外部任务的情况下启动本地服务。
5. 涉及可见前端页面时默认只跑源码与自动布局烟测；只有用户明确要求浏览器检查、视觉回归或手动验收时，才打开浏览器并覆盖指定视口。
6. 明确区分“自动测试通过”“浏览器快速烟测通过”和“用户已手动验收”，不能把前两者写成用户验收完成。

本地快速烟测不包括：真实图片/视频/语音付费生成、真实发布、供应商回传、批量写业务数据、Git 推送、服务器部署或生产数据修改。

### 2. 自动扩大为针对性验证的情况

出现以下任一情况时，应在快速烟测基础上增加相应测试和读写闭环验证：

- 修改登录、游客、成员、团队、供应商或角色权限。
- 修改积分预占/结算、订阅权益、支付展示或模型调用计量。
- 修改 SQLite schema、数据迁移、草稿同步、Blob、上传、删除、发布、回撤或幂等逻辑。
- 修改视频长任务、取消、恢复、重试、媒体合成、字幕或缓存标识。
- 修改无限画布源码、托管 vendor、父子应用消息协议或 iframe 鉴权。
- 修改批量生产与单号生产之间的项目映射、资产归属或交付状态。
- 修复曾经发生过的数据覆盖、权限串数据、白屏、缓存混版或部署差异。

针对性验证应覆盖涉及的单元测试/API、必要的浏览器流程、失败分支和数据非回退检查。涉及真实付费调用或生产写入时仍需用户明确授权，不能因为风险高就自行执行。

### 3. 完整验收与生产操作

- 只有用户明确要求“仔细验收”“完整视觉回归”“真实生成”“发布”“提交/推送”或“部署”时，才进入对应完整流程。
- 完整视觉回归再扩展到多个桌面/移动视口、截图、控制台、网络失败和关键交互矩阵。
- 真实模型调用应控制次数和费用，先验证配置与最小请求，再执行目标任务。
- Git 提交、推送、部署、外部发消息和生产数据变更必须遵守用户授权与交接边界。
- 生产部署必须使用干净、可审计的目标提交和精确资源清单，并验证数据基线、服务健康和纯代码回滚点。

### 检查遇到阻塞时

- 测试或服务无法运行时，说明具体原因、已完成的替代检查和剩余风险，不伪造通过结果。
- 发现工作区已有陌生修改时保留原样；只有与本次文件重叠且无法安全继续时才询问用户。
- 发现文档写法与当前代码不一致时，以实时证据为准，并把文档失真作为本版需要收口的事项。

## 当前产品入口

- 游客可以进入首页、查看订阅和有限资产入口；真正发起创作时再登录或注册。
- 个人账号拥有视频工坊、无限画布、语音生成和个人整体资产；每日积分按中国时区结算，生成类接口使用“预占、成功结算、失败释放”。
- 团队账号增加数据看板、批量生产、账号和成员协作、供应商交付、发布清单、数据分析和团队管理。
- 订阅管理目前是本地方案与权益展示，没有接入真实支付；ACG 内部团队按现有内部权益处理。
- 首页统一输入可把提示词和附件交接到视频工坊或无限画布；工作区左栏统一管理视频、画布和批量任务的上下文。
- 首页灵感发现读取真实社区帖子；分享保持源作者和团队归属，收藏按个人隔离。已分享产出不得重复发布，同一媒体的分享状态由服务端幂等记录恢复。
- 整体资产按个人 / 专业 / 团队权限投影草稿、本人媒体、收藏和后台素材；普通个人不获得团队发布账号筛选能力。

## 主业务模型

核心生产对象为 `production`：

- 图文：图文创作台 -> 审核 -> 交付。
- 数字人：数字人制作 -> 智能混剪 -> 审核 -> 交付。
- 信息流/素材视频：视频生成与素材编排 -> 智能混剪 -> 审核 -> 交付。
- 批量生产负责账号选择、账号级文案、参考图和批次启动；单号工作台负责具体生产、修正与交付。

账号、成员、团队、供应商、资产、发布和分析等权威业务数据由主服务控制。前端隐藏按钮不能替代服务端权限校验。

## 定制创作边界

### 视频工坊

- 独立 FastAPI sidecar 监听 `127.0.0.1:8765`，隔离新版 FastAPI/Pydantic、`faster-whisper`、FFmpeg 和长时媒体任务。
- 主平台通过 `/custom-video/` 签发当前成员会话、限制 owner 范围并代理 API、附件和成片。
- 项目、上传和输出保存在 `runtime/video-workshop/`；成功镜头、口播和成片支持保留与恢复，不得被代码部署覆盖。
- 动态任务与静态任务使用独立执行链：动态进入 Seedance，静态使用图片分镜、TTS、字幕、BGM 和 FFmpeg 渲染，不得把静态任务误送 Seedance。
- 静态画面使用固定中心的连续慢速放大；分镜长度按口播和语义自然拆分，只要求整体时长大致合理，不建立精确时长或强制口播约束。
- iframe 与 `postMessage` 是账号、样式、事件和长任务隔离边界；没有真实性能证据和灰度回退方案前不取消。

### 无限画布

- 源码位于 `apps/infinite-canvas-source/`，生产托管产物位于 `vendor/infinite-canvas/`，由主服务在 `/XZ-Design/` 提供。
- React/Zustand 子应用负责画布交互、节点、视口、参考图和浏览器导出；模型密钥、权限、生成、编辑和服务端草稿由主服务负责。
- 项目摘要与本地 checkpoint 按成员分仓；完整草稿同步到服务端，使用 revision、冲突保护和删除 tombstone。
- 新生成图片先固化为 owner-scoped Blob URL，再写入画布 checkpoint；旧内联 Base64 草稿在正常读写时惰性迁移。
- 批量生成最多三路并发，并有取消、超时和中断边界；单张失败不阻塞整批，旧执行态恢复为可重试中断而不自动生成或扣点。
- 当前静态产物由 `apps/infinite-canvas-source/` 源码构建，共 61 个文件、`1761292` bytes；相对路径、大小和 SHA-256 manifest 已校验，`vendor/infinite-canvas/` 已按该审计闭包精确同步，不再保留历史多余哈希文件。

## 身份、团队与积分边界

- 游客状态不是服务器成员身份，不得访问团队业务和受保护生成接口。
- 公共注册先建立个人账号；加入团队和团队角色通过后续申请、审批和成员关系决定。
- 团队所有者、管理员、编辑、普通成员和供应商角色的能力由服务端接口逐项校验。
- 个人每日积分和外部有限套餐在模型调用前原子预占，成功后按实际用量结算，失败、取消或中断后释放；幂等键必须绑定请求摘要和任务终态。
- 动态视频在成功终态按提交模型与归一化请求时长对应费率结算；静态视频按本轮新生成图片及存在且本轮新生成的 TTS 实际用量结算，历史复用媒体不重复收费。ACG 市场部精确走无限积分旁路。
- 供应商初始凭据只允许在首次受控响应中出现，响应必须禁止缓存；不得写入日志、文档或聊天。

## 字幕与语音边界

- 数字人自动字幕以分段口播原文为内容真源，以每段实测音频或视频时长为时间边界。
- 信息流字幕只读取最终视频提示词中的时间段和可验证说话上下文，排除 UI、道具文字、元数据和导演说明。
- 视频工坊对用户主动上传的外部音频可在 sidecar 内使用 `faster-whisper`；该依赖和模型缓存与主平台字幕链隔离。

## 数据与部署边界

- 主业务数据位于服务端 SQLite、上传目录、合成目录和受控 Blob/runtime 路径；生产必须使用 release 目录外的固定绝对路径，不得随版本切换。
- `.env.local`、服务器环境变量、API Key、认证缓存、数据库、上传、成片、日志、浏览器状态和模型缓存不得提交 Git。
- `runtime/`、`server/canvas_blobs/`、`apps/video-workshop/.venv/` 和生产持久卷不得被静态同步覆盖。
- v135 的 P0 门禁是：先加载环境再导入应用 / store；持久路径固定在 release 外；用带 version/checksum/status 的显式迁移账本取代启动隐式迁移；租户鉴权 deny-by-default；`/api/ready` 验证 release、schema、SQLite、路径、sidecar 和画布 manifest；依赖必须锁定并可离线安装，不得在启动时联网升级。
- 部署只能使用精确审计的代码 / 静态发布包和独立迁移阶段；回滚默认只切换到经过验证、可读取扩展后数据库的兼容回滚 release。生产一旦产生 v135 新写入，原始 v120 不再是有效回滚目标；任何回滚都不得用旧数据库或旧媒体覆盖新业务。
- `deploy/README.md` 和 `deploy/start_server.sh` 是旧流程，不可用于 v135 生产部署。唯一权威方案是 `docs/本地代码架构优化与服务器迁移部署方案.md` 与 `docs/服务器部署交接指南.md`。
