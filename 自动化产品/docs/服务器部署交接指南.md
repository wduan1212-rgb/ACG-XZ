## 0. 本文件怎么使用

本文件分成三类内容：

- 固定基线：项目目录、云环境、服务目录、systemd 服务、端口、凭据安全获取方式、数据边界和部署硬规则。除非基础设施变化，否则长期保留。
- 带日期的运行快照：最近确认的线上版本、账号基线、当前故障和待部署修复。它们可能变化，每次交接前必须重新核对并更新时间。
- 待填交接模板：真正需要换线程时，由当前线程读取线上状态、Git 状态和相关文档后填写。没有开始交接时保持模板状态。

以后用户把本文件交给当前服务器部署线程并要求交接时，当前线程必须：

1. 保留固定基线，不重新猜服务器结构。
2. 刷新带日期的运行快照，删除已经失效的临时结论。
3. 完整填写第 12 节“本次交接记录”，不能只发一句概括。
4. 把填写后的交接内容发给用户指定的新线程。
5. 明确哪些事实是已验证、哪些来自日志、哪些仍待验证。

## 1. 最高原则

1. 服务器上的运行态数据是唯一生产事实，优先级高于本地代码、Git 仓库、部署包和浏览器缓存。
2. 普通版本部署只允许更新代码与静态资源。不得用本地数据、种子数据或空状态覆盖服务器数据。
3. 任何部署前必须先备份、确认回滚点、做同步预演；部署后必须核对数据计数和真实业务链路。
4. 不得在 Markdown、Git、聊天、提交信息、命令摘要或日志摘要中写明文服务器地址、用户名、密码、API Key、token、Authorization 或账号凭据。
5. 不得为了解决页面显示异常而清库、重建账号、删除上传文件或覆盖 `.env*`。
6. 当前工作区可能同时被多个线程修改。未经确认不得还原、覆盖、暂存或提交其他线程的改动，不得使用 `git add .`。

4. `docs/version.md`：读取目标版本；目标未定时只看顶部最近 1 至 3 个版本。
5. `docs/Problem Document.md`：按目标模块、接口、缓存、权限、数据或部署风险关键词检索；无相关命中就停止。

## 4. 线上数据边界

以下内容属于生产运行态，任何普通功能升级都必须原样保留：

- `server/data.sqlite`、`server/data.sqlite-*` 及其他实际数据库文件。
- `server/data.json` 等兼容或历史状态文件。
- `server/uploads/`：用户上传和资产原文件。

- `server/logs/`：运行日志，仅可轮转，不得随代码同步删除。
- `.env`、`.env.local` 和服务器私有环境配置。
- 认证缓存、第三方登录态、浏览器或 OpenCLI 运行态。
- 服务器 `.venv/`、模型文件、二进制工具和私有依赖。
- 账号、成员、角色、供应商关系和账号分配。
- productions、jobs、sessions、batches、drafts、voicePresets 等业务文档。
- 整体资产、账号资产、共享/私有标记和真实文件。
- 发布清单、发布链接、发布人、下载状态和回传备注。
- 数据分析链接、指标快照和历史统计。
- 删除墓碑 `deleted_docs`。删除墓碑是阻止旧浏览器缓存复活数据的必要生产数据，不能清空。

### 共享与隔离口径

- 全局共享：账号基础资料、明确共享/已发布资产、发布清单、数据分析、管理员允许共享的配置。
- 按用户或权限隔离：未发布草稿、单号创作过程、批量任务、session、batch、私有素材、未发布生成结果。
- 管理员可以管理成员和全局已发布数据，但不能因为部署而获得其他成员未发布私有素材。
- 删除和新增必须以服务器为权威。不能让旧浏览器 IndexedDB 把已删数据重新回推。

v120 部署记录中的账号基线为 80 个：50 个小红书图文账号和 30 个视频号账号。它不是当前实时保证；部署前后都要按生产 `/api/state` 或数据库实际数据重新建立基线。发现数量异常时先查旧缓存回推、重复 ID 和账号墓碑，不要直接重新播种。

## 5. 绝对禁止的部署动作

- 禁止把本地 `server/data.sqlite*`、`server/data.json` 上传到生产。
- 禁止上传本地 `server/uploads/`、`server/composed/`、`server/logs/` 覆盖生产。
- 禁止上传本地 `.env*`、开发 Key、认证缓存或 `.venv/`。
- 禁止对生产目录直接执行未经排除规则验证的 `rsync --delete`。
- 禁止使用 `git reset --hard`、`git clean -fdx` 或清空生产目录再上传。
- 禁止用本地空 state、账号种子或浏览器 IndexedDB 重建线上数据。
- 禁止在没有备份和计数基线时执行 schema 迁移或数据清理。
- 禁止只看 `/api/*/config` 的绿色状态就声称模型可用；必须跑真实最小请求。
- 禁止只更新入口 HTML 而漏掉 ES 子模块缓存号；浏览器必须加载同一版本模块图。
- 禁止把服务器临时热修当成最终版本。代码问题应回传代码线程，形成可追踪提交后再部署。

## 6. 标准部署流程

本节是旧版普通代码/静态更新的通用流程，**不适用于 v136**。v136 含本地 community schema 增量，必须先完成 `docs/本地代码架构优化与服务器迁移部署方案.md` 中的 fail-closed 数据路径、显式迁移账本、强制只读、`/api/ready`、恢复演练与兼容回滚 release；不能直接执行“同步、restart、health”。

### 6.1 明确目标版本

部署前必须得到：

- 已批准的 commit 完整或短哈希。
- 对应 `docs/version.md` 版本号。
- 对应静态资源缓存身份集及每个入口的 canonical URL。
- 本版是否有数据库 schema 增量；如果没有，明确写“只更新代码和静态资源”。
- 本版必须验收的页面、接口和真实模型链路。

不要把“本地最新文件”当成部署目标，必须以用户批准的提交为准。

### 6.2 使用干净源码

当前主工作区经常包含其他线程未提交修改。推荐从批准提交建立临时 worktree：

```bash
git fetch origin
git worktree add --detach /tmp/acg-xz-deploy-<commit> <commit>
```

部署完成后再移除临时 worktree。不要在主工作区执行破坏性清理。

### 6.3 连接后先做只读盘点

```bash
cd /data/dumate-studio/current
pwd
systemctl is-active dumate-studio.service
systemctl status dumate-studio.service --no-pager
df -h
du -sh server/uploads server/composed 2>/dev/null
```

同时记录但不要在聊天中暴露：当前代码提交、入口缓存号、数据库文件时间与大小、账号/资产/发布清单/草稿计数、服务启动时间。

### 6.4 创建备份与回滚点

至少保留：

- 部署前代码目录或发布包。
- 数据库及 WAL/SHM 伴随文件。
- 旧 JSON 状态文件。
- 上传与合成目录的清单、大小和必要快照。
- `.env*` 的服务器本地备份，权限保持为仅管理员可读。
- 当前 systemd 配置和依赖版本清单。

备份目录必须位于生产同步目录之外，使用时间戳命名。备份完成后核对文件存在和大小，不要只相信命令退出码。

### 6.5 同步预演

同步前先 dry-run，排除至少以下内容：

```text
.env
.env.*
.venv/
server/data.sqlite*
server/data.json
server/uploads/
server/composed/
server/logs/
backups/
认证缓存与第三方登录态
```

普通更新不使用 `--delete`。如确需删除废弃静态文件，必须先列出具体文件并证明它们不是运行态数据。

### 6.6 更新代码并重启

只在同步结果确认后更新代码和静态资源，然后：

```bash
systemctl restart dumate-studio.service
systemctl is-active dumate-studio.service
systemctl status dumate-studio.service --no-pager
curl -fsS http://127.0.0.1:8787/api/health
```

重启失败时先看本次服务日志和 Python/JS 语法错误，不得通过清库或覆盖环境文件尝试修复。

## 7. 部署后最低验收

### 7.1 版本与冷启动

- 未登录冷启动页面不白屏。
- 登录后入口加载该 release 批准的静态缓存身份集。
- 浏览器 Network 中 `index.html`、`main.js`、目标业务模块均来自批准 identity set，且每个模块只有一个 canonical URL；供应商独立标识不要求与主入口相同。
- Console 无未捕获错误、循环导入错误或旧模块变量错误。

### 7.2 数据保护

- 账号数量与部署日只读基线一致；v120 记录中的 80 只能作历史对照，不能代替实时计数。
- 成员、供应商关系和账号分配没有减少或串权限。
- 整体资产、账号资产、发布清单、发布链接、草稿、数据分析计数不减少。
- 随机抽查已有图片、音频和视频文件能预览与下载，不是蓝色占位或只有 TXT。
- 删除墓碑表仍存在，删除草稿/账号后刷新不复活。

### 7.3 三角色权限烟测

- 管理员：可进入管理员允许页面，不能看其他成员未发布私有创作。
- 供应商管理员：只看到自己供应商范围内账号和发布清单。
- 供应商子账号：只看到分配给自己的账号和允许的交付内容。
- 发布清单继续显示真实发布账号/发布人，不因快照或权限投影丢字段。

### 7.4 双客户端同步烟测

使用 A、B 两个独立浏览器会话：

1. A 新增测试账号，B 刷新可见。
2. B 删除测试账号，A 刷新后消失。
3. A、B 再次刷新/重登，测试账号不能复活。
4. A 上传测试图片并设为共享/发布，B 可见真实图片并能下载。
5. 未发布私有素材在另一成员视角不可见。
6. 测试完成后按正常远端删除流程清理，不直接改数据库。

### 7.5 模型真实检查

配置接口只证明“有配置并能连到域名”，不证明模型可生成。真实模型检查会产生外部调用或费用，必须另获用户授权；未授权时明确记为待验收。获授权后至少检查：

- LLM：`/api/llm/config` 后调用 `/api/llm/test`。
- TTS：`/api/tts/config` 后调用 `/api/tts/test` 或最短口播生成。
- 图片：`/api/image/config` 后分别跑一张无参考图和一张带参考图的最小生成。
- Seedance：`/api/video/config` 后提交一个短任务，必须拿到 providerRef，并轮询到 output。
- OmniHuman：使用有效角色图与口播音频提交一段，必须验证 providerRef、轮询结果和同源视频预览。
- JustOneAPI：配置检查后跑一条真实 fetch。

模型测试不得在回复中粘贴完整 data URL、临时资源 URL、Key 或 Authorization。

## 9. 常见故障判断顺序

### 页面还是旧版

1. 核对服务器磁盘文件是否为目标 commit。
2. 核对该 release 批准的缓存身份集。
3. 核对每个 ES 子模块只有一个批准的 canonical URL；供应商独立标识不要求与主入口相同。
4. 使用全新浏览器上下文冷启动，不只依赖普通刷新。
5. 不要清数据库或上传目录。

### 数据删除后复活

1. 检查 DELETE 是否真正返回成功。
2. 检查 `deleted_docs` 墓碑是否存在。
3. 检查旧浏览器 IndexedDB 是否大批量回推。
4. 检查服务器是否拒绝异常批量未知 ID。
5. 不要用重新播种或清表解决。

### 图片/语音/视频配置显示正常但生成失败

1. 先跑真实最小请求并保留脱敏 HTTP 状态和错误类别。
2. 区分 DNS、TCP/TLS、鉴权、额度、模型名、endpoint、payload、限流、轮询和结果下载。
3. 403/405 等应用层响应说明网络已通，不应误报成网络故障。
4. 对图片同时检查无参考图与参考图路径；对视频同时检查 submit 和 poll。
5. 如果本地可用而服务器失败，比较服务器出口、Base、完整 path、模型和请求体，不要只比较 Key。

### 资产有记录但无法预览或下载

1. 检查资产文档的文件 ID/URL 是否指向服务器同源文件。
2. 检查真实文件是否存在于 uploads/composed。
3. 检查权限投影是否只下发了记录而未允许文件读取。
4. 检查视频 Range 请求是否返回 206。
5. 不要用蓝色占位或 TXT 清单冒充资产成功。

## 10. 回滚规则

- 开放 v136 写入后，只能回滚到已验证能读取扩展 schema、保持新租户/账号/配额语义的兼容前向 release；原始 v120 只作为历史基线，不能直接读取 v136 演进库。
- 默认不回滚数据库，也不恢复旧数据库覆盖部署后新增业务数据；先冻结写入并保存事故后的数据库和媒体，再执行兼容代码切换或前向数据修复。
- 只有维护窗全程冻结、能够证明一致性快照之后没有任何业务或 runtime 写入，并获得用户明确批准时，才可把数据库与全部受保护媒体作为同一一致性点整体恢复；不得只恢复其中一部分。
- 新迁移默认 expand-first，保留新增表/列；“旧代码能忽略新列”不等于它理解新权限与写入语义。
- 回滚后重新跑健康检查、数据计数、三角色权限和受影响模型最小链路。
