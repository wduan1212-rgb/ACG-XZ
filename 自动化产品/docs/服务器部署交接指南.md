## 1. 最高原则

1. 服务器上的运行态数据是唯一生产事实，优先级高于本地代码、Git 仓库、部署包和浏览器缓存。
2. 普通版本部署只允许更新代码与静态资源。不得用本地数据、种子数据或空状态覆盖服务器数据。
3. 任何部署前必须先备份、确认回滚点、做同步预演；部署后必须核对数据计数和真实业务链路。
4. 不得在 Markdown、Git、聊天、提交信息、命令摘要或日志摘要中写明文服务器地址、用户名、密码、API Key、token、Authorization 或账号凭据。
5. 不得为了解决页面显示异常而清库、重建账号、删除上传文件或覆盖 `.env*`。
6. 当前工作区可能同时被多个线程修改。未经确认不得还原、覆盖、暂存或提交其他线程的改动，不得使用 `git add .`。

### 6.6 显式迁移、只读启动与门禁

应用启动不会自动迁移。唯一顺序是
`137003`→`137004`→`139001`→`140001`→`140002`→`140003`→`140004`。`137004`、`140002`、`140004`
各自先只读 preflight；`140002` 只可选使用精确且哈希绑定的 override manifest。每个 apply 前
必须立即生成 fresh v2 SQLite 备份，上一步成功后不得复用旧 manifest。主服务、
sidecar、后台任务和其他 writer 全程停止或强制冻结；只有当次 CLI 进程可临时
`ACG_READ_ONLY=0` 并带对应 ALLOW/版本/identity/backup SHA-256。

`140002` 后历史资源 scope 必须 100%，unresolved/ambiguous 阻断，陈旧次要引用只能 warning。
无自动证据孤儿的 override 只能在 writer 冻结的维护窗生成为精确人工复核 manifest，并绑定
database identity、path/logical digest、schema/user version 与 fresh backup manifest SHA。使用它时 resource-preflight
也必须传 `--backup-manifest`、`--backup-database`、`--confirm-backup-manifest-sha256`；apply 在同一
`BEGIN IMMEDIATE` 内重验全部绑定。
`140004` 对无引用孤立文件 quarantine 且不开放；有引用缺 owner/文件或归属歧义必须阻断。

已审计 release 只读启动后，以受 token 保护的 readiness 为准：

```bash
curl -fsS -H "X-Readiness-Token: $ACG_READY_TOKEN" \
  http://127.0.0.1:8787/api/ready
curl -fsS http://127.0.0.1:8765/api/health
```

`/api/health` 只证明进程可访问，不证明版本、SQLite、迁移、持久路径或
sidecar 兼容。任一 readiness 检查失败都不得切流。失败时不得通过清库、
覆盖环境文件或在服务器上重建 manifest 尝试绕过。

生产 native 继续使用两个独立 `systemd Type=simple` 单元作为唯一进程所有者。
禁止在它们运行时另调 `deploy/start_server.sh`；该脚本只能在两单元已停止的
隔离维护场景使用，且对 pidfile / 端口监听者必须同时匹配 service、cwd、
executable 和命令行后才可 TERM；任一身份不匹配均零信号、阻断备份与启动。

切 RW 前还要审计两单元的 `Restart=on-failure` 和直指批准 release 的 ExecStart/
WorkingDirectory/EnvironmentFile，并由 systemd timer 持续检查主 `/api/ready` 与 sidecar
`/api/health`。timer 只跑轻量 readiness，不得调用 snapshot、media preflight/apply
或全媒体 SHA-256。现场没有该 unit/timer 证据时，不得宣称已具备持续门禁。

## 7. 部署后最低验收

### 7.1 版本与冷启动

- 未登录冷启动页面不白屏。
- 登录后入口加载该 release 批准的静态缓存身份集。
- 浏览器 Network 中 `index.html`、`main.js`、目标业务模块均来自批准 identity set，且每个模块只有一个 canonical URL；v137 主入口和供应商视图使用同一已审计缓存身份。
- Console 无未捕获错误、循环导入错误或旧模块变量错误。

### 7.2 数据保护

- 账号数量与部署日只读基线一致；v120 记录中的 80 只能作历史对照，不能代替实时计数。
- 成员、供应商关系和账号分配没有减少或串权限。
- 整体资产、账号资产、发布清单、发布链接、草稿、数据分析计数不减少。
- 随机抽查已有图片、音频和视频文件能预览与下载，不是蓝色占位或只有 TXT。
- 删除墓碑表仍存在，删除草稿/账号后刷新不复活。

v137 只读迁移验收期间不执行新增、删除、上传、生成或发布类业务写入烟测；
这些项目只在后续完成资源 scope/媒体 registry 并获得开放写入授权后执行。

### 7.3 三角色权限烟测

- 管理员：可进入管理员允许页面，不能看其他成员未发布私有创作。
- 供应商管理员：只看到自己供应商范围内账号和发布清单。
- 供应商子账号：只看到分配给自己的账号和允许的交付内容。
- 发布清单继续显示真实发布账号/发布人，不因快照或权限投影丢字段。

### 7.4 双客户端同步烟测（仅解除只读并另获写入授权后）

本小节不是 v137 只读迁移验收的一部分。只有资源 scope、媒体 registry、迁移备份绑定
等 P0 已完成，用户另行批准开放写入后，才使用 A、B 两个独立浏览器会话：

1. A 新增测试账号，B 刷新可见。
2. B 删除测试账号，A 刷新后消失。
3. A、B 再次刷新/重登，测试账号不能复活。
4. A 上传测试图片并设为共享/发布，B 可见真实图片并能下载。
5. 未发布私有素材在另一成员视角不可见。
6. 测试完成后按正常远端删除流程清理，不直接改数据库。

### 7.5 模型真实检查

配置接口只证明“有配置并能连到域名”，不证明模型可生成。真实模型检查会产生外部调用或费用，必须另获用户授权；未授权时明确记为待验收。获授权后至少检查：

- LLM：`/api/llm/config` 后调用 `/api/llm/test`。
- TTS：`/api/tts/config` 后调用 `/api/tts/test` 或最短口播生成。
- 图片：`/api/image/config` 后分别跑一张无参考图和一张带参考图的最小生成。
- Seedance：`/api/video/config` 后提交一个短任务，必须拿到 providerRef，并轮询到 output。
- OmniHuman：使用有效角色图与口播音频提交一段，必须验证 providerRef、轮询结果和同源视频预览。
- JustOneAPI：配置检查后跑一条真实 fetch。

模型测试不得在回复中粘贴完整 data URL、临时资源 URL、Key 或 Authorization。

## 9. 常见故障判断顺序

### 页面还是旧版

1. 核对服务器磁盘文件是否为目标 commit。
2. 核对该 release 批准的缓存身份集。
3. 核对每个 ES 子模块只有一个批准的 canonical URL，且 v140 主入口/供应商视图统一到同一缓存身份。
4. 使用全新浏览器上下文冷启动，不只依赖普通刷新。
5. 不要清数据库或上传目录。

### 数据删除后复活

1. 检查 DELETE 是否真正返回成功。
2. 检查 `deleted_docs` 墓碑是否存在。
3. 检查旧浏览器 IndexedDB 是否大批量回推。
4. 检查服务器是否拒绝异常批量未知 ID。
5. 不要用重新播种或清表解决。

### 图片/语音/视频配置显示正常但生成失败

1. 先跑真实最小请求并保留脱敏 HTTP 状态和错误类别。
2. 区分 DNS、TCP/TLS、鉴权、额度、模型名、endpoint、payload、限流、轮询和结果下载。
3. 403/405 等应用层响应说明网络已通，不应误报成网络故障。
4. 对图片同时检查无参考图与参考图路径；对视频同时检查 submit 和 poll。
5. 如果本地可用而服务器失败，比较服务器出口、Base、完整 path、模型和请求体，不要只比较 Key。

### 模型用量为 0 但成员确实生成过内容

1. 先按中国时区精确换算半开日期窗口，并确认成员唯一 ID、角色和实际登录身份。
2. 同时查询中央 usage、主平台任务/输出映射和视频工坊 runtime；不能只看设置页汇总。
3. 若项目或 provider receipt 可证明成功而 usage 为空，标记为遥测覆盖缺口；不要补造 token、调用次数或日期。
4. 检查是否来自旧版 sidecar、TTS/音色、`role=user` 汇总遗漏或 usage 写入失败；v139 以后还要核对 receipt/outbox/spool readiness。历史恢复只对隔离副本运行 evidence manifest，不直接改旧事件或活动库。

### 资产有记录但无法预览或下载

1. 检查资产文档的文件 ID/URL 是否指向服务器同源文件。
2. 检查真实文件是否存在于 uploads/composed。
3. 检查权限投影是否只下发了记录而未允许文件读取。
4. 检查视频 Range 请求是否返回 206。
5. 不要用蓝色占位或 TXT 清单冒充资产成功。

## 10. 回滚规则

- 执行七步迁移任一 apply 后，只能回滚到已验证理解 v140 schema、租户、媒体和配额语义的兼容前向 release；原始 v120 只作为历史基线。
- 默认不回滚数据库，也不恢复旧数据库覆盖部署后新增业务数据；先冻结写入并保存事故后的数据库和媒体，再执行兼容代码切换或前向数据修复。
- 只有维护窗全程冻结、能够证明一致性快照之后没有任何业务或 runtime 写入，并获得用户明确批准时，才可把数据库与全部受保护媒体作为同一一致性点整体恢复；不得只恢复其中一部分。
- 新迁移默认 expand-first，保留新增表/列；“旧代码能忽略新列”不等于它理解新权限与写入语义。
- 回滚后重新跑健康检查、数据计数、三角色权限和受影响模型最小链路。
