# ACG 市场部生产团队迁移计划

记录日期：2026-08-02

状态：**仅记录，尚未获部署授权，尚未连接或修改服务器。**

本文件用于未来用户明确批准团队鉴权版本部署时的受保护迁移。它不是部署命令，也不能替代部署当日对生产实况、目标 commit、维护窗口和回滚点的重新核对。

## 1. 迁移目标与固定映射

- 在生产数据原地建立内部团队 `ACG市场部`，不重新播种、不复制整库、不改变既有账号凭据。
- 生产唯一主管理员 `admin` 映射为 `ACG市场部` 所有者；迁移前后用户名、密码哈希和登录方式保持不变。
- 其他既有管理员映射为 ACG 团队管理员。
- 既有创作者映射为 ACG 团队成员。
- 当前供应商父账号、子账号、供应商分配关系和平台账号归属 ACG；供应商端仍是独立工作区，不进入创作者首页。
- 既有平台账号、资产、草稿、生产单、任务、批次、发布清单、发布回链、统计、uploads、composed、canvas blobs、视频工坊 runtime 与历史媒体按现有关联增量归入 ACG。
- 迁移完成后新注册的个人账号默认保持个人租户；未来外部订阅团队建立自己的团队和供应商关系，不自动并入 ACG。

## 2. 部署前硬条件

必须同时满足：

1. 用户明确批准目标 commit、部署范围和维护窗口。
2. 使用批准提交建立干净临时 worktree 或审计发布包，不能直接同步当前脏工作区。
3. 冻结生产写入，记录服务状态、代码版本、入口缓存号、数据库路径和数据计数基线。
4. 在生产同步目录之外创建并验证完整回滚点：
   - SQLite 主文件以及 WAL/SHM；
   - uploads、composed、canvas blobs、视频工坊 runtime 与历史媒体；
   - `.env*`、认证状态和 systemd 配置；
   - 当前代码与静态闭包。
5. 读取并比较主管理员凭据哈希，但不得打印、转述或写入部署记录。
6. 对目标代码做 schema/readiness 检查；禁止仅凭 `/api/health` 认定迁移兼容。

## 3. 副本演练

从生产备份创建隔离副本，并在与生产相同的 Python、SQLite、环境变量和启动方式下执行：

1. 第一次运行增量迁移，记录新增/更新/跳过数量。
2. 第二次运行相同迁移，必须不产生重复团队、成员、供应商映射或资源归属。
3. 确认主管理员凭据哈希与迁移前一致，默认配置不得改写已有密码。
4. 对迁移前后以下计数逐项核对，任何业务计数不得下降：用户、管理员、创作者、供应商父子账号、平台账号、资产、草稿、任务、批次、发布清单、回链和 canvas blobs。
5. 执行 SQLite `quick_check`，结果必须为 `ok`。
6. 验证登录与权限矩阵：ACG 所有者、ACG 管理员、ACG 成员、供应商父账号、供应商子账号、个人用户、外部团队用户、游客。
7. 验证租户隔离：个人和外部团队不可读取 ACG 私有草稿、任务、平台账号或资产；ACG 不会因兼容旧数据而收纳未来新个人资源。

副本演练未连续两次通过时，禁止进入生产切换。

## 4. 生产执行顺序

1. 重新确认写入冻结、服务状态和回滚点可读。
2. 仅同步审计后的代码与静态文件；不得覆盖数据库、媒体、私密配置、认证缓存或运行态目录。
3. 以单实例执行幂等 schema 与团队归属迁移，保留脱敏迁移摘要。
4. 启动主平台 `8787`，确认视频工坊 sidecar 仍仅通过本机 `127.0.0.1:8765` 接入；无限画布使用审计后的静态闭包。
5. 先执行 readiness、SQLite 和数据计数核对，再开放浏览器只读验收。
6. 完成角色登录、团队申请、供应商端、平台账号、资产、草稿、发布清单、社区和视频/画布集成验收后，才解除写入冻结。

## 5. 通过标准

- 数据计数不下降，文件目录大小与清单无异常减少。
- SQLite `quick_check=ok`，服务健康与 readiness 均通过。
- `admin` 显示为 `ACG市场部 · 所有者`，其他管理员和创作者角色正确。
- 当前供应商端绑定 ACG 且仍展示独立首页、全部账号和发布清单。
- 个人与外部团队数据隔离；未来注册不会自动归入 ACG。
- 生产真实最小链路按当次授权范围完成，且失败扣点、退款、资产持久化和发布回链一致。

## 6. 回滚原则

- 未开放新写入前发生故障：停止服务，恢复部署前代码、静态闭包和完整数据库/媒体回滚点，再跑完整性与计数检查。
- 已开放新写入后发生故障：先再次冻结写入并保存事故后数据库与媒体，再使用兼容/反向迁移；不得用旧数据库盲目覆盖新业务数据。
- 向后兼容的新增表和列可保留给旧代码忽略；任何数据恢复都必须获得用户再次确认。
- 回滚后重新验证健康、SQLite、数据计数、三类创作角色、供应商层级和租户隔离。

## 7. 永久禁止事项

- 禁止用本地 SQLite、种子状态、uploads、composed 或 canvas blobs 覆盖生产。
- 禁止 reset、clean、清库、重新播种或整目录覆盖来解决权限/显示问题。
- 禁止在聊天、Git、Markdown 或日志摘要中记录明文服务器地址、密码、密钥、token 或凭据哈希。
- 禁止把“本地已提交”“自动测试通过”描述为“已推送”“已上线”或“已完成生产验收”。
